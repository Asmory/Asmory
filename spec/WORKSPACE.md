# Project Workspace — Draft 0.1

Asmory separates **user intent**, **resolved reality**, and **local working
materialization**.

The first project layout is:

```text
project/
|-- asm.toml
|-- asm.lock
`-- .asmory/
    |-- .gitignore
    `-- deps/
```

## `asm.toml` — user intent

The manifest is authored by the user or an agent.

```toml
schema = 1

[workspace]
resolver_policy = "asmory-v1"

[dependencies]
```

Future dependency declarations live under `[dependencies]`.

## `asm.lock` — exact chosen reality

The lockfile is generated by Asmory and is intended to be committed.

```toml
schema = 1
resolver_policy = "asmory-v1"
dependency_count = 0
```

Future records will bind Project/Release, Capability, Semantic Fingerprint,
Profile if used, Provider, Machine Variant, Artifact SHA-256, trust decision
and resolver policy version.

The lockfile is not a cache. It is the reproducible record of what the resolver
chose.

## `.asmory/deps/` — local working materialization

Resolved source will later be materialized here by default.

The directory is intentionally visible to humans and AI agents but ignored from
Git while dependencies remain **Exact** and reconstructible from the lockfile.

> **Local-visible by default, Git-tracked when diverged.**

This milestone creates the directory but does not fetch packages yet.

## Initialization safety

`asmory init`:

- performs no network access;
- downloads nothing;
- executes no package code;
- never overwrites an existing `asm.toml` or `asm.lock`;
- is idempotent when both files already exist;
- refuses a partial state where only one of those files exists.

Acquisition is a later stage.
