Publishing

Asmory is a package index, not a Git forge. Publish immutable releases that tools and agents can resolve safely.

01

Describe the project

asm.toml carries package metadata, links, dependencies and the machine contract.

02

Validate the release

The client checks name normalization, version identity, target/ISA constraints, exported symbols and archive contents.

03

Upload once

A published project/version/artifact identity is immutable. Fixes require a new version.

04

Yank, don't rewrite

A broken release may be yanked from future resolution without deleting the historical artifact.

The intended CLI flow

The current CLI is still a bootstrap; these commands define the registry-facing workflow we are building toward.

$ asmory login
$ asmory publish --check
$ asmory publish

Registry invariants

NAME

One normalized project identity

Lookup is case-insensitive; runs of ., _ and - normalize to one hyphen.

RELEASE

Version history is append-only

Published versions are historical records. Metadata needed for resolution is captured with the release.

ARTIFACT

Every file is content-verified

Download metadata carries size and SHA-256 so clients verify bytes before assembly or linking.
